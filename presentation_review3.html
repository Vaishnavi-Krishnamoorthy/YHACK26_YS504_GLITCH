Problem Statement
Speaker: Vaishnavi S
Security & Integrity Vulnerabilities in Air-Gapped Vision Pipelines
1. Data Layer Attack Vectors
  • Frequency Domain Backdoors: High-frequency checkerboard patterns and imperceptible trigger watermarks injected into training images.
  • Annotation Corruption: Manipulated bounding boxes and inverted coordinates in COCO and YOLO label files.
  • Duplicate Flooding: Near-duplicate sample injection that creates severe class bias in trained models.
2. Model Layer Threats
  • Model Substitution: A legitimate verified neural network is silently swapped with a compromised or backdoored weight file.
  • Weight Drift & Mutation: Unauthorized fine-tuning altering classifier heads while leaving lower feature extraction intact.
3. Operational & Inference Threats
  • Distribution Drift: Real-world operational feeds departing significantly from training distribution (weather, lighting, sensor dirt).
  • Post-Inference Tampering: Modification of saved detection logs, bounding boxes, or confidence records after execution.
The Air-Gapped Security Gap (The Core Challenge)
Critical computer vision systems (defense drones, autonomous robotics, nuclear inspection) operate in isolated, air-gapped environments with zero cloud connectivity.

Existing safety solutions rely entirely on cloud APIs. There is currently no unified offline framework that cryptographically binds training data, neural weights, and inference outputs.

Proposed Solution

AEGIS-CV: Unified Cross-Layer Offline Assurance Architecture
System Concept & Operation
AEGIS-CV ingests 4 standard vision artifacts locally:
  • Dataset: Training image directories and label annotations (COCO/YOLO).
  • Model: Neural network weight files (ONNX, PyTorch .pt/.pth).
  • Config: Pipeline hyperparameter specifications and class manifests.
  • Inference Records: Operational runtime logs and detection boxes.
Executes 5 modular verification engines 100% offline, yielding a deterministic composite risk score and tamper-evident audit receipt.
Tri-State Automated Decision Engine
Instead of ambiguous warnings, AEGIS-CV generates actionable operational triage commands:
  • ACCEPT (Score 0–30): Pipeline mathematically verified authentic; cleared for operational deployment.
  • REVIEW (Score 31–65): Moderate anomaly or distribution drift; flagged for human inspection.
  • QUARANTINE (Score 66–100): Critical backdoor, weight mutation, or Merkle breach; execution blocked immediately.

Implementation
Speaker: Vaishnavi K
Core Engines: Data Assurance & Model Integrity
Module 1: Data Assurance Engine
  • 2D FFT Frequency Poison Scanner:
    Computes 2D Fast Fourier Transform on training images: $$F(u,v) = \sum_{x} \sum_{y} f(x,y) e^{-j2\pi(\frac{ux}{M}+\frac{vy}{N})}$$ Sub-perceptual backdoor triggers (BadNets, checkerboards) exhibit abnormal high-frequency energy ratios. Flags images where high-frequency energy ratio exceeds baseline (> 0.38).
  • Perceptual dHash Duplicate Detection:
    Resizes images to 9x8, computes adjacent horizontal pixel gradients, and constructs a 64-bit fingerprint to detect near-duplicate frames via Hamming distance.
  • Annotation Boundary Validation:
    Strict format parsing for YOLO (validates $0.0 \le x,y,w,h \le 1.0$) and COCO bounding boxes. Rejects inverted coordinates and negative dimensions.
Module 2: Model Integrity Engine
  • Layer-by-Layer Weight Fingerprinting:
    Dissects neural network weight tensors (e.g. conv1.weight, features.dense, head.fc.bias). Computes individual SHA-256 digests per layer.

    Capability: When an unauthorized party fine-tunes or substitutes specific model layers, AEGIS-CV pinpoints the exact mutated layer rather than just reporting general corruption.
  • Black-Box Behavioral Fallback:
    For encrypted or proprietary model architectures where weights cannot be inspected, AEGIS-CV probes the model with calibrated synthetic noise triggers and monitors output prediction flip rates.
  • Framework Agnostic:
    Native support for ONNX graphs, PyTorch state dictionaries, and TorchScript models.

Modules 3, 4 & 5: Drift, Cryptographic Provenance & Risk Engine
Module 3: Inference Drift & Authenticity
  • Operational Drift Detection: Tracks live camera confidence distributions and evaluates out-of-distribution (OOD) shift via statistical Z-score analysis ($Z > 2.5$).
  • Output Record Verification: Hashes saved bounding boxes and class scores to prove historical prediction logs were not manipulated post-generation.
Module 4: Cryptographic Provenance Chain
  • Hierarchical Merkle Tree: $$\text{SHA256}(\text{Dataset}) + \text{SHA256}(\text{Model}) + \text{SHA256}(\text{Config}) \rightarrow \text{Merkle Root}$$
  • Tamper-Evident Receipts: Signed locally via HMAC and stored in receipts/pipeline_receipt.json. A single altered byte in any artifact immediately breaks root validation.
Module 5: Composite Risk Scoring & Triage Matrix
Synthesizes weighted anomaly penalties from all 4 upstream engines into a normalized 0 to 100 composite risk score: $$R_{\text{total}} = w_d R_{\text{data}} + w_m R_{\text{model}} + w_i R_{\text{drift}} + w_p R_{\text{prov}}$$

Architecture
Speaker: Tarun Pranav RS
Automated Verification Workflow & Chained Audit Ledger
Six-Step Verification Lifecycle
  1. Local Registration: Offline ingestion of Dataset, Model, Config, and Inference Logs.
  2. Chunked Streaming Hashing: 64KB block streaming computes SHA-256 digests with constant memory overhead.
  3. Multi-Vector Analysis: Concurrently triggers 2D FFT scan, layer weight comparison, and statistical drift profiling.
  4. Risk Score Aggregation: Normalizes penalties into a unified 0 to 100 composite risk score.
  5. Deterministic Triage: System enforces ACCEPT, REVIEW, or QUARANTINE action.
  6. Ledger Block Sealing: Appends cryptographically chained record into the audit ledger.
Tamper-Evident Chained Audit Ledger
Brings blockchain-grade tamper evidence to air-gapped system logs:
  • Chained Block Structure: Stored in receipts/audit_ledger.jsonl. Each entry records block_index, timestamp, merkle_root, risk_score, triage_action, and the previous_hash.
  • Backwards Validation: The ledger engine verifies block integrity across the entire historical chain. Any retroactive modification or record deletion breaks previous-hash continuity instantly.
  • Zero Cloud Stack: Python 3.13, NumPy, Pillow, PyTorch, ONNX Runtime, Streamlit, hashlib, hmac. Fully self-contained.
